## 평가 원칙

- **행동으로 판정한다.** 문서 품질이 아니라, 스킬을 읽은 모델이 정해진 순간에 정해진 행동을 하는지 본다.
- **강제와 부탁을 따로 센다.** 훅·도구 제한·설정이 막는 것과 프롬프트 문장으로만 막는 것은 다른 결함이다.
- **모델별로 시험한다.** 역할마다 배정 모델과 대조 모델(opus↔sonnet)을 각 2회. 2회 결과가 갈리면 문장이 모호하다는 신호다.
- **맥락을 분리한다.** 무맥락 리뷰를 먼저, 맥락 리뷰를 나중에. 실행자는 정답지를 보지 않고, 채점자는 실행자와 다른 인스턴스다.
- **비파괴.** 샌드박스 레포와 오프라인 `gh` 대체본에서만 돌린다.

## 변경 등급별 시험

등급은 diff로 정한다. 여러 등급에 걸치면 가장 높은 등급, 애매하면 높은 쪽. E2E는 C4에서만 돌린다.

| 등급 | 대상 | 시험 |
|---|---|---|
| C0 문구 | 의미가 바뀌지 않는 설명·예시·오탈자 | 문자열 계약 대조만 |
| C1 스크립트 | `scripts/*.py`, `templates/githooks/*` | 대응 `tests/*_scenarios.sh` 전건 + `PY=/usr/bin/python3`로 1회 |
| C2 문자열 계약 | 복원·머지가 grep하는 커밋 접두, 보고 키(`result:`·`contracts:`·`Tests:`), `state.json` 키 | 같은 리터럴이 모든 파일에서 일치하는지 대조 |
| C3 게이트·전이 | 전이 규칙, 복원 표 행, 사람 게이트, 단계 순서 | C2 + 해당 상황 시나리오 2회(opus·sonnet) |
| C4 오케스트레이션·외부 변화 | 에이전트·호출 방식·훅 이벤트·모델 기본값, Claude Code 버전·모델 세대 교체 | C3 + E2E light 1회(필수), 계약 경로에 닿으면 full 1회 + 모델 비교 |

- 문자열 계약 대조 스크립트·복원 시나리오 스크립트는 아직 없다. 생기기 전까지 C0·C2는 바꾼 리터럴을 `grep -rn`으로 플러그인 전체에서 찾아 대조한다.
